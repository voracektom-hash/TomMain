Riziko 1

Kvalita migrovaných dat

Duplicity a nekonzistentní DIČ v kmenových datech
Vysoké
Kmenová data dodavatelů a zákazníků obsahují duplicity a chybné identifikátory z pěti zdrojových systémů.
Mitigace: data cleansing workshop, automatická validace, dedicated data steward na plný úvazek.
Riziko 2

Dostupnost klíčových lidí

Přetížený key-user financí kolem uzávěrek
Vysoké
Hlavní key-user financí má v červnu paralelně čtvrtletní uzávěrku, hrozí zdržení UAT o dva až tři týdny.
Mitigace: formální alokace 40 % FTE, backup key-user, přesun části úloh na konzultanta.
Riziko 3

Integrace na bankovní API

Externí dodavatel posouvá specifikaci rozhraní
Střední
Banka již podruhé posunula termín dodání specifikace platebního API. Bez něj nelze dokončit integraci plateb.
Mitigace: eskalace přes CIO, příprava dočasného manuálního importu, kontraktuální penále.

Problém 1 · v řešení

Nekonzistentní kmenová data

V SAPonátu dnes běží pět systémů s různými ID zákazníků. Potřebujeme jednotný master před migrací.

  • Dopad: zdržení migrace o tři týdny
  • Vlastník: Jan Novák, data team
  • Další krok: automatická deduplikace do 25. 4.
Problém 2 · eskalováno

Výkon reportingu nad velkými sklady

Standardní reporty nad dvěma miliony položek trvají 45 sekund. Uživatelé už reagují negativně v UAT předzkoušce.

  • Dopad: revize indexů a materializovaných pohledů
  • Vlastník: Petr Dvořák, ERP konzultant
  • Další krok: POC indexace do 29. 4.
Problém 3 · čeká rozhodnutí

Scope creep v HR modulu

Personální oddělení žádá navíc evidenci školení a rozvojových plánů mimo původní rozsah projektu.

  • Dopad: +250 konzultantských dní nebo posun do fáze 2
  • Vlastník: steering committee
  • Další krok: rozhodnutí na jednání 22. 4.
Další kroky

Akce na následující dva týdny

  • Dokončit cleansing dodavatelských dat do 25. 4.
  • Spustit UAT scénáře pro modul finance od 28. 4.
  • Zajistit alokaci backup key-usera do 22. 4.
  • Eskalovat specifikaci bankovního API přes CIO do 18. 4.
